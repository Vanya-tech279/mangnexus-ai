# MangNexus AI — Backend

FastAPI service providing the two prediction endpoints the frontend expects
(see the Phase 7–9 comments in `mockData.js`, `ZoneAnalysis.jsx`, and
`ProductionRisk.jsx`).

## Phase history

- **Phase 7** built this API's routes and schemas, with `scoring.py`
  driven by a transparent weighted-average heuristic as a stand-in for a
  real model.
- **Phase 8 (current)** trains two scikit-learn `RandomForestClassifier`
  models and swaps them into `scoring.py` in place of the heuristic
  classification. The routes, request/response schemas, and the display
  "score" formula are all unchanged — Phase 9's frontend integration needs
  no changes because of this swap.
- **Phase 9** points the frontend's `fetch()` calls at this API instead of
  its mock `result` objects.

## ⚠️ Demo/sample data disclaimer

Verified MOIL operational data was not available for this SIH prototype.
Both models in `app/models/` are trained on **synthetic demo datasets**
generated by `ml/datasets.py` — realistic distributions and domain-grounded
weights, but not real historical records. `GET /model-info` reports
`"data_source": "synthetic_demo"` for exactly this reason, and the same
flag should be surfaced on the Data Hub page. Swapping in real data later
only means replacing the two `generate_*_dataset()` functions with a loader
for verified records — `train_zone_model.py` / `train_risk_model.py` and
everything downstream stay the same.

## Setup

```bash
cd backend
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Train the models (required before first run)

```bash
python -m ml.train_all
```

This writes `app/models/{zone,risk}_model.joblib` and matching
`*_meta.json` files (feature order, class list, held-out validation
accuracy, dataset size). Re-run any time `ml/datasets.py` changes, or once
real operational data replaces the synthetic generators. Trained artifacts
are already included in this checkout, so this step is only needed if
you've deleted `app/models/` or changed the training data.

## Run

```bash
uvicorn app.main:app --reload --port 8000
```

Interactive docs at `http://localhost:8000/docs`.

## Endpoints

### `GET /health`
Returns `{"status": "ok", "models_loaded": true}`.

### `GET /model-info`
Validation accuracy, class list, and training/test set sizes for both
models — e.g.:

```json
{
  "loaded": true,
  "zone_model": {
    "classes": ["High", "Low", "Medium"],
    "validation_accuracy": 0.8738,
    "train_samples": 3200,
    "test_samples": 800,
    "model_type": "RandomForestClassifier",
    "data_source": "synthetic_demo"
  },
  "risk_model": { "...": "..." }
}
```

### `POST /predict-zone`
Request body (matches `miningZones[].parameters` in mockData.js):

```json
{
  "mineralReflectanceIndex": 82,
  "geologicalFormationMatch": 88,
  "historicalDrillingProximity": 76,
  "ironOxideCorrelation": 79,
  "terrainSlopeSuitability": 91,
  "vegetationStressIndex": 64
}
```

Response (matches `miningZones[].result` shape):

```json
{
  "potential": "High",
  "score": 81,
  "accuracy": 87,
  "confidence": 91,
  "indicators": ["..."],
  "insight": "...",
  "recommendation": "..."
}
```

`accuracy` is the trained model's held-out validation accuracy (fixed per
model, from `zone_model_meta.json`); `confidence` is that specific
prediction's class probability from the model (varies per request) — this
is the Model Accuracy vs Prediction Confidence distinction the project
brief calls for.

### `POST /predict-risk`
Request body (matches `productionSites[].inputs` in mockData.js):

```json
{
  "avgMonthlyProduction": 356,
  "equipmentAvailability": 68,
  "equipmentDowntimeHours": 142,
  "forecastRainfallMm": 210
}
```

Response (matches `productionSites[].result` shape):

```json
{
  "risk": "Medium",
  "score": 59,
  "accuracy": 83,
  "confidence": 83,
  "factors": ["..."],
  "insight": "...",
  "actions": ["..."]
}
```

Note: unlike the Phase 7 heuristic, the trained risk model also learns from
`avgMonthlyProduction` — Phase 7 collected that field but never weighted it
into the score. For this exact example the Phase 7 heuristic would have
said "High"; the trained model says "Medium" for the same inputs. The
`score` shown is still computed by the original 3-factor formula (so it's
unchanged at `59`), but the *label* now comes from the model, and a real
model reading the four signals together is allowed to land somewhere the
old fixed formula didn't. If you'd rather the flagship demo site
(`avgMonthlyProduction: 356, ...`) stay "High" for continuity with the
existing UI mock data, that's a one-line tweak to the risk feature weights
in `ml/datasets.py` — flag it and I'll retune and retrain.

## What Phase 9 does with this

`ZoneAnalysis.jsx` and `ProductionRisk.jsx` currently simulate a model call
with `setTimeout`. Phase 9 swaps that for:

```js
const res = await fetch('http://localhost:8000/predict-zone', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(selectedZone.parameters),
})
const result = await res.json()
```

and flips `IS_DEMO_DATA` to `false` in `mockData.js`.
